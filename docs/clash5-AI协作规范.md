# clash5 AI 协作规范

> 配套：[`clash5-工程手册.md`](clash5-工程手册.md)（r2 修订稿，待冻结）、[`clash5-M0-M6-任务拆解.md`](clash5-M0-M6-任务拆解.md)。仓库代理须同时遵守根目录 `AGENTS.md`；项目负责人的明确任务要求优先。
> 本文件约定建议的协作与交付格式，不替代仓库现行贡献规则。工具、账号、执行位置由具体任务确定。

## 1. 角色分工

| 角色 | 职责 | 边界 |
| --- | --- | --- |
| **协调者** | 拆解任务、定义验收、汇总结论、对接项目负责人 | 按项目负责人授予的权限推进评审与合并；对交付物做约束检查 |
| **实现者** | 在授权工作区修改代码、提交 PR、运行测试 | 遵守手册与 `AGENTS.md`；不提交密钥与订阅数据 |
| **浏览器/桌面代理** | GUI 或网站操作，如查阅文档、核对发布页 | 是否修改仓库取决于任务授权与工具能力 |
| **本地执行** | 仓库开发、脚本、文档整理与必要验收 | 使用隔离分支或工作树，保留可审查的变更 |

实现者可以是任一编码 Agent。若项目负责人指定某个模型或工具，以指定为准；未指定时按可用性选择。**无论选用哪个实现者，brief 与验收标准相同。**

## 2. 任务粒度

- 单次任务对应**一个里程碑子项或一个垂直切片**，预计一个 PR 可审完。
- 反例：「做完整个插件系统」「重做全部 UI」。
- 正例：「M3.1：PatchMerger 与单测，含路径白名单校验」「节点详情的生效配置表与 `plugins/effective_config` IPC」。

## 3. Brief 模板

每条任务的 brief 必须包含以下字段，缺一不发出：

```text
Repo: <仓库地址>
Milestone: <里程碑与子项编号，如 M0.2>
Model requirement: <如有强制要求，如 Opus-class；否则写 none>
Goal: <可验证的结果，不写实现步骤>
Hard constraints: <手册 §2 的条目编号 + 相关决策代号>
Out of scope: <本次明确不做的事>
Done when:
- <可执行的验收项，如测试命令或手测步骤>
- <...>
Hypothesis (verify): <协调者的假设，允许实现者否定>
Delivery: 向 <分支> 提交 PR；PR 描述包含「解决什么 / 如何验证 / 未覆盖项」
```

**说明**：

- `Hypothesis` 必须标为假设，实现者发现与之不符时应在 PR 中说明，不得静默按假设实现。
- `Done when` 中的每一项都应能被第三方独立执行。
- 仓库变更遵守根目录 `AGENTS.md` 的 issue、提交语言与 PR 署名要求；brief 不得用模板字段替代实际验证证据。

## 4. Opus 批次约定

- 任务拆解中标为 `[Opus]` 的条目，brief 须明确 `Model requirement: Opus-class`。
- 涉及身份、补丁合并、热更回滚、注入路由的任务，视为高风险，默认归为 Opus 批次。
- 标准批次可使用常规编码模型。

## 5. 交付与审核

1. 实现者提交 PR 后，协调者按以下顺序检查：
   - 是否满足 `Done when` 全部条目；
   - 是否违反手册 §2 任一硬约束；
   - 是否新增日志输出含凭证或订阅 URL（可用 §1.4 的脱敏测试样本复查）；
   - 是否修改了 §1.1 所列的上游接触点之外的既有文件（如有，需在 PR 中说明）。
2. 检查通过后，将结论与风险登记表（`clash5-风险登记.md`）中相关条目对照；设计已定而代码未验收的风险保留为开放，实现有新风险时更新登记表。
3. 合并依项目负责人的当前授权执行；已有明确授权时不重复索取确认。

## 6. 跟进与纠偏

- 实现者长时间无进展时，协调者可补充说明或收缩任务范围，而不是另起一个并行任务抢同一分支。
- 同一工作流的后续修改在原 PR 上完成，不另开 PR。
- 项目负责人要求暂停时，协调者应停止派发新任务，并记录当前进度。

## 7. 用户指定其它编码工具时

- 同一份 brief 交给指定工具，验收标准不变。
- 同样须遵守手册硬约束：不绕过 GPL 义务、不提交密钥、注入默认关闭。
- 指定工具产出的 PR 同样走 §5 的审核流程。

## 8. 子任务示例（起步批次）

| 编号 | 内容 | 批次 |
| --- | --- | --- |
| CA-1 | Fork 基建：独立 identifier 与目录、CI 骨架（T2 矩阵）、上游 tag 同步文档 | 标准 |
| CA-2 | `StableId`（含版本字段）、`BindingStore`（WAL + 迁移）、provider diff 与孤儿处理 | Opus |
| CA-3 | 节点池路由与 i18n 词条占位（无业务逻辑） | 标准 |

后续批次（CA-4 至 CA-10）按任务拆解和当前进度编写。M0 已按原基线合并，M1 已启动；r2 新增差距单列追踪，不回写为已通过项。
