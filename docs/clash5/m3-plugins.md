# M3 插件 Host

第三方插件以 `.c5p` ZIP 包安装，包内必须且只能包含 `manifest.json`、`module.wasm`、`manifest.minisig` 和 `signer.pub`。签名覆盖 manifest 原始字节，manifest 中的 SHA-256 覆盖 WASM 字节。安装对话框展示签名者指纹与权限；用户确认的公钥随插件保存在应用数据目录。指纹用于复核同一签名者，签名本身不会证明发布者真实身份。

WASM ABI 导出一页或多页线性内存 `memory` 和函数 `apply(ptr, len) -> i64`。Host 在模块初始线性内存之后追加 JSON `{ "configuration": ..., "binding": ... }`，并将其指针和长度传给 `apply`，避免覆盖模块静态数据；返回值低 32 位是补丁指针，高 32 位是补丁长度。未声明 `config.read` 时，Host 传入空配置对象；每个绑定必须声明 `config.patch`。Host 校验返回 JSON 对象中的每条路径都落在 manifest 的 `writable_paths` 前缀内。第三方 WASM 不得声明导入项；Host 不提供网络或文件系统接口，并限制单次最多 32 个启用绑定、线性内存 32 MiB、fuel 和 epoch 执行时间 3 秒。

`sample-plugin.wat` 返回一个 `/tun/mtu` 补丁。以 WAT 编译为 WASM 后，将模块 SHA-256 写入 manifest，以 minisign 对 manifest 原始字节签名，再按上述四个固定文件名打包。示例不包含签名密钥；插件作者应自行保管私钥。

配置生成在 Merge/Script 与链路生成之后读取当前启用的插件绑定。所有适用插件先执行，补丁按优先级降序、绑定 ID 升序合并；较高优先级对同一字段获胜。合并器会记录被覆盖字段的胜出与落败绑定，插件页展示有效值、来源和冲突；有效配置 API 会将密码、密钥、令牌、认证信息、UUID 与 URL 脱敏。插件不可写用户规则。补丁集通过路径校验后整体转换并交给现有 Mihomo 配置校验；生成或校验失败时绑定定义恢复，原运行配置再次生成。

设置页展示最近 50 条插件审计事件。安装成功会记录插件版本、签名者指纹和声明权限；同一次配置生成中成功执行的插件合并为一条 `plugin.apply` 汇总，记录每个绑定的插件 ID、绑定 ID、声明权限与耗时；加载或执行失败逐条记录错误码。存储层对审计字段做白名单过滤，审计元数据不包含绑定设置、有效配置值或凭证。审计写入失败会保留在应用诊断日志中，不阻断核心配置生成。

绑定页支持批量新建、单项编辑、启用/停用和移除。插件本身可以停用：停用时其目录写入 `disabled` 标记，配置生成跳过该插件的全部绑定，绑定记录保留；启用即删除标记。启停与配置生成在同一事务内回滚，并分别记录 `plugin.enable` 或 `plugin.disable` 审计事件。卸载插件会删除其目录，仍被任何绑定（包括孤儿绑定）引用的插件拒绝卸载，需先删除绑定；卸载记录 `plugin.uninstall` 审计事件。设置页按签名者列出已安装插件；撤销某签名者的信任会停用其全部插件（绑定保留），需在确认对话框中确认，并记录 `plugin.signer.revoke` 审计事件。参数仅在用户明确编辑某绑定时解密到设置表单，保存前重新以 AES-GCM 封装；每次应用都会经现有配置生成和校验，失败时恢复原绑定。

绑定参数在存储前使用应用现有 AES-GCM 封装；当前密钥由应用目录中的本地密钥文件保护，尚未迁移到操作系统密钥库。
