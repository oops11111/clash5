# 线下真机验证清单

本文件供线下（Windows 真机）验证使用。所有已在 Linux 或 CI 上完成的验证都不重复列入；这里只列需要真实桌面、真实 Windows 行为或人工判断的项目。

## 1. 分支与版本

- 分支：`claude/proxy-architecture-privacy-5w0fr4`（远端 `origin`）。
- 尚未开 PR，因此本分支不代表已合并的 `dev`。
- 验证前在仓库根目录执行 `git rev-parse --short HEAD`，把输出记入每条回报。
- 本清单对应的 issue：#50–#60。每个项目括号内给出 issue 编号。
- 验证过程中不得修改代码。发现问题请按第 4 节回报，由开发侧修复后再开新的验证基准。

## 2. 环境

- Windows 10 或 11 x64。需要管理员权限（服务安装、凭据管理器读写）。
- 版本以仓库为准：Rust `1.99.0`（`rust-toolchain.toml`），Node `24.21.0`，pnpm `12.11.2`（`.tool-versions`）。
- 需要 Visual Studio Build Tools（MSVC）与 WebView2 运行时。
- 构建：

  ```powershell
  pnpm install
  pnpm prebuild        # 下载 mihomo sidecar 并构建服务
  pnpm build           # tauri build，产物位于 src-tauri\target\release
  ```

- 测试用节点只能使用自有服务器或本地夹具。禁止使用真实订阅链接、真实令牌或他人的节点。
- 本地两跳夹具：`scripts/fixtures/socks-hop.py`，在两个终端分别运行

  ```powershell
  python scripts\fixtures\socks-hop.py A 1081 %TEMP%\hops.log
  python scripts\fixtures\socks-hop.py C 1083 %TEMP%\hops.log
  ```

  日志每行记录一个经过该跳的 `CONNECT`。
- 目标站点：`pnpm m1:probe-fixture 18080 forward` 或任意本地 HTTP 服务。
- 测试前建议使用全新的应用数据目录，以避免旧 DNS 配置文件影响 #51。

## 3. 任务清单

每项记录：`[ ]` 未做，`[x]` 通过，`[!]` 失败，`[-]` 阻塞（无法执行，写明原因）。

### A. 基线

- [ ] A1 安装、启动、退出各一次，无崩溃；托盘可用。
- [ ] A2 关闭后再次启动，设置、订阅、节点、链路、路由、插件均保留。
- [ ] A3 首页 IP 卡片默认关闭（#52）。
- [ ] A4 设置 → 其他 中「自动检查更新」默认关闭（#53）。

### B. controller 密钥（#50）

- [ ] B1 启动后，运行时配置中的 `secret` 不是 `set-your-secret`，且为 64 位十六进制字符（应用数据目录中的运行时配置）。
- [ ] B2 `curl.exe http://127.0.0.1:9097/version` 不带认证返回 401。
- [ ] B3 带运行时配置中的 secret 访问返回 200。
- [ ] B4 重启应用后 secret 改变，旧 secret 返回 401。

### C. DNS（#51）

- [ ] C1 全新数据目录启动后，DNS 配置文件中 `listen` 为 `127.0.0.1:53`。
- [ ] C2 `netstat -ano -p UDP` 中 53 端口只绑定 `127.0.0.1`，没有 `0.0.0.0:53`。
- [ ] C3 默认 `nameserver` 只有两个 DoH 地址，没有 `8.8.8.8` 或 `system`。
- [ ] C4 既有 DNS 配置文件（升级前的文件）不被改写（用升级前的文件做对照）。

### D. 隐私（#53、#52）

- [ ] D1 空闲 10 分钟，记录应用的外连（`Get-NetTCPConnection` 按进程过滤）。不应出现更新检查或 IP 卡片的外连。
- [ ] D2 打开首页 IP 卡片后，才出现 IP 查询请求，且只访问 `PRIVACY.md` 列出的服务。
- [ ] D3 对照 `PRIVACY.md` 第 4、5 节，逐条确认描述与实际行为一致。不一致请回报。

### E. 凭据与密钥（#58）

- [ ] E1 全新安装启动后，凭据管理器中存在 `io.github.oops11111.clash5` / `encryption-key`，且 `%APPDATA%\...\.encryption_key` 不存在。
- [ ] E2 迁移：用升级前的构建创建 WebDAV 设置和一个插件绑定，然后升级到本分支。升级后 `.encryption_key` 被删除，凭据管理器中有对应条目，WebDAV 设置和绑定仍可读取。
- [ ] E3 迁移失败保护：升级前在凭据管理器中删除该条目，再启动。应用应报错，且不得在数据目录中生成新的 `.encryption_key`，也不得静默换密钥。
- [ ] E4 凭据管理器不可用时（如临时禁用）保存设置，应报错而不是回退到文件。

### F. 插件（#54、#55）

- [ ] F1 安装 `scripts/fixtures/m3-acceptance-plugin.c5p`。安装预览显示「新的签名者」提示（#55）。
- [ ] F2 再次预览同一包，提示变为「该签名者已有 1 个已安装插件」（#55）。
- [ ] F3 绑定插件后，「停用」插件：绑定保留，有效配置中该插件的补丁消失；「启用」后恢复（#54）。
- [ ] F4 有绑定时点击「卸载」：应被拒绝，给出可读的错误（#54）。删除绑定后卸载成功。
- [ ] F5 设置页撤销该签名者的信任：确认对话框列出插件；确认后插件被停用，绑定保留（#55）。
- [ ] F6 升级：需要维护者提供同一签名者、更高版本的测试包（不在仓库中）。升级预览显示版本变化与新增权限；升级后「回滚」按钮出现，回滚后版本恢复（#54）。
- [ ] F7 降级：用更低版本的包覆盖安装，应被拒绝（#54）。
- [ ] F8 市场：输入 `http://` 地址应被拒绝；输入不可达的 https 地址，应显示错误而不是空列表（#60）。
- [ ] F9 市场（需要维护者提供的 https 目录）：添加目录时，预览显示签名者指纹，确认后目录出现；下载包后进入安装预览（#60）。

### G. 链路与代理池（#56）

- [ ] G1 两跳链路：创建链路，两跳分别为 `A`（1081）与 `C`（1083）的 SOCKS 节点（作为手动节点导入）。测试连通性成功。两个夹具的日志都出现来自该链路的 `CONNECT`（#56）。
- [ ] G2 三跳加代理池：第二跳选择包含两个成员的池。测试连通性成功；保存后重新打开，链路结构不变（#56）。
- [ ] G3 删除池：池仍被链路使用时应被拒绝；删除链路后再删除池成功（#56）。
- [ ] G4 固定出口：检测出口后点击「固定最近一次的出口地址」，保存。修改链路（如换第二跳）后再次检测，出现漂移告警，历史中有 `漂移` 记录（#56）。
- [ ] G5 历史：每次检测或测试都在检查器的历史中新增一条记录，且重启后仍在（#56）。
- [ ] G6 旧链路兼容：升级前创建的两跳链路（front/landing 格式）打开后显示为两跳，保存后仍可用（#56）。

### H. 应用路由（#57）

- [ ] H1 进程路由：复制 `curl.exe` 为 `appA.exe`。路由 `appA.exe` 到链路 G1。运行 `appA.exe -x http://127.0.0.1:<mixed-port> <目标>`：流量经过两跳；运行原始 `curl.exe`：直连（日志无新增 `CONNECT`）。
- [ ] H2 进程路径：用绝对路径的路由（如 `C:\...\appA.exe`）重复 H1，结果一致。
- [ ] H3 直连与拒绝：路由 `Direct` 与 `Reject` 生效。
- [ ] H4 域名策略：路由一个域名后缀到 `Reject`，访问该域名失败，其他域名不受影响。域名解析器（可选）可在 mihomo 日志中看到对应的 DoH 请求。
- [ ] H5 启用/停用路由后，重新生成配置即刻生效；删除被路由引用的链路应被拒绝。

### I. 综合与稳定性

- [ ] I1 连续运行 30 分钟，执行 G1 与 H1 各三次，应用不崩溃，托盘可用。
- [ ] I2 切换订阅配置后，属于其他配置的链路与路由不导致生成失败（#56、#57）。

## 4. 结果回报

### 回报途径

1. 按 `#50`–`#60` 对应的 issue 评论回报，每个 issue 一条评论，列出该 issue 下所有已执行的项目。
2. 失败项单独评论，并在标题中写明项目编号（如「F7 降级未被拒绝」）。
3. 阻塞项在同一条评论中说明原因（如「没有维护者提供的更高版本包」）。
4. 日志与截图先脱敏再附上。不得包含订阅链接、令牌、节点密码、用户名或真实出口 IP。

评论使用以下模板：

```text
### <项目编号>，<结果：通过 / 失败 / 阻塞>
- 验证基准（提交）：
- 环境（Windows 版本、构建方式、是否全新数据目录）：
- 操作与实际现象：
- 期望与差异：
- 日志或截图（已脱敏，路径或附件名）：
- 备注：
```

### 回报时机

- 每完成一个分组（A–I）回报一次，不必等全部完成。
- 发现安全相关问题（例如密钥泄露、未经授权的网络请求）请立即回报，并在评论中注明「安全」。
